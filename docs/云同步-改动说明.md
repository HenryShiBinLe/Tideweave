## 对现有项目的影响

- **游戏代码**：`src/` 下原有的文件都没改，也没有任何游戏代码引用 `src/sync/`，所以 `npm run build` 打出来的 `dist/app.js` 里没有同步代码（已检查）。
- **桌面版**：`desktop/` 和打包脚本都没改。桌面版照旧完全离线、不联网，存档仍然写在原来的 `data/progress.json`。
- **依赖**：`package.json`、`package-lock.json` 都没改，没有新增依赖。服务端只用 Node 自带的模块。
- **`npm test`**：会自动多跑 `tests/` 里新增的 `sync-*.test.mjs`，共 55 项：合并 18 项、调度 13 项、服务端 13 项、端到端 7 项、修改时间 2 项、同步码 2 项。原有的 87 项不变。全部跑完约 6 秒。这些测试只在本机临时起服务（随机端口、临时目录，跑完自动清理），不联网，也不读写游戏存档。
- **`npm start`、`npm run package`**：不受影响。
- **运行时数据**：服务端在本机运行时会把数据写到 `server/data/`，这个目录已被 `Tideweave/.gitignore` 里的 `data/` 规则忽略，不会被提交。

## 第二次改动：前端接入（10/20，分支 `feat/sync-frontend`）

按协作约定第六部分接入三处，只改了下面 4 个已有文件：

| 文件 | 改了什么 |
|---|---|
| `src/main.mjs` | ① 读档、存档入口改为经过同步层（网页版才创建同步层，桌面版照旧走 `window.tideweave`）；② 设置弹窗加“云同步”区：开启、输入同步码、显示同步码和状态、立即同步、关闭；首页底栏显示同步状态；③ 拉到新进度时沿用 `importSave()` 的处理（停止播放、清空 `sessionCache`、替换、保存、重画），玩家在关卡里或开着别的弹窗时不应用，退出后约 2 秒内自动应用 |
| `src/game.css` | 文末追加云同步区的样式，不改原有样式 |
| `src/index.html` | CSP 的 `connect-src 'none'` 改为 `'self'`：只允许连回页面所在的地址（同步接口）。原来的写法会让浏览器直接拦掉同步请求 |
| `src/sync/index.mjs` | 只改注释：CSP 只允许同源，本机开发要让同步服务同时托管网页 |

**桌面版不受影响**：检测到 `window.tideweave` 就不创建同步层；`desktop/main.cjs` 拦截所有网络请求的设计没动。在 macOS 上用 Playwright 启动隔离目录里的 Electron 检查过：设置里没有云同步区，底栏仍是“本地存档 · 自动保存”，页面没有发出任何对外请求，主动 `fetch` 也被拦下，没有页面报错。

**验证**（本机同步服务同时托管 `dist/`，用 `localhost` 和 `127.0.0.1` 两个不同源的标签页模拟两台设备，各自的 localStorage 互相独立）：

1. 设备 A 已有 3 关进度，开启云同步，第一次同步把进度传到云端（服务端数据目录里能看到这 3 关）；
2. 设备 B 是全新进度，输入 A 的同步码（故意用小写、不带横线），拿到 A 的 3 关，应用前在本机留了备份；
3. 在 B 上实际点击打通 01-02.1，约 5 秒后自动推送；A 切回前台时自动同步，进度从 3/43 变为 4/43，“继续游戏”推进到下一关；
4. A 在关卡里时，B 切换了章节：A 同步后不替换存档，设置里显示“其他设备的新进度会在退出关卡后载入”；A 退出关卡后约 2 秒自动载入并提示；
5. `npm test` 149 项全部通过，`npm run build` 成功。

## 第三次改动：静态文件缓存（10/20 晚）

只改了我们自己的 `server/index.mjs`：托管网页时，文件名带 8 位内容哈希的素材（如 `assets/nodes/node_well.15b7045d.webp`）返回 `Cache-Control: public, max-age=31536000, immutable`，浏览器第二次打开直接用缓存；其他文件照旧 `no-cache`，每次向服务器确认。新增 1 项测试（改之前先确认它失败）。仓库里现有的素材文件名不带哈希，所以对现在的构建结果没有影响。
