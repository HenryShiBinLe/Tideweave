# 云同步 · 改动说明

**一句话**：这次只新增文件，没有修改或删除任何已有文件。同步层还没有接进游戏，网页版和桌面版的表现都和原来一样。

双方的约定见 [协作约定-存档与云同步.md](协作约定-存档与云同步.md)，设计和验证细节见 [云同步-技术方案.md](云同步-技术方案.md)，本文不重复。

## 新增了什么

| 位置 | 内容 |
|---|---|
| `Tideweave/src/sync/`（8 个文件） | 同步层：存档合并、同步码、修改时间记录、HTTP 收发、一次同步的流程、同步调度、给前端用的入口 |
| `Tideweave/server/`（7 个文件） | 同步服务端（零依赖的 Node 程序）、运维脚本、部署配置（systemd 和无 root 常驻脚本）、测速页、使用说明 |
| `Tideweave/tests/sync-*.test.mjs`（6 个文件） | 同步层和服务端的测试，共 55 项 |
| `docs/云同步-技术方案.md`、本文 | 方案与验证记录、改动说明 |

## 对现有项目的影响

- **游戏代码**：`src/` 下原有的文件都没改，也没有任何游戏代码引用 `src/sync/`，所以 `npm run build` 打出来的 `dist/app.js` 里没有同步代码（已检查）。
- **桌面版**：`desktop/` 和打包脚本都没改。桌面版照旧完全离线、不联网，存档仍然写在原来的 `data/progress.json`。
- **依赖**：`package.json`、`package-lock.json` 都没改，没有新增依赖。服务端只用 Node 自带的模块。
- **`npm test`**：会自动多跑 `tests/` 里新增的 `sync-*.test.mjs`，共 55 项：合并 18 项、调度 13 项、服务端 13 项、端到端 7 项、修改时间 2 项、同步码 2 项。原有的 87 项不变。全部跑完约 6 秒。这些测试只在本机临时起服务（随机端口、临时目录，跑完自动清理），不联网，也不读写游戏存档。
- **`npm start`、`npm run package`**：不受影响。
- **运行时数据**：服务端在本机运行时会把数据写到 `server/data/`，这个目录已被 `Tideweave/.gitignore` 里的 `data/` 规则忽略，不会被提交。
